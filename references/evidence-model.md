# 证据模型：五级证据、判定规则与 Automation 特例

证据等级由脚本按输入中的检查记录确定性判定（../scripts/runmodel.py 的
decide_evidence 纯函数），语言模型没有授予或升级等级的通道；叙事文件中
不携带任何等级字段，页面徽标一律由脱敏后的运行模型渲染。

## 五级定义

| 等级 | 页面标签 | 含义 |
|---|---|---|
| external-verification | 外部复验 | 存在与验收条件匹配且明确通过的验证记录 |
| failed | 验证失败 | 该主张对应的验证记录中存在明确失败 |
| tool-evidence | 工具证据（未复验） | 无验证记录，但有文件修改、命令、检索等工具调用记录 |
| unverified | 未验证 | 无验证记录、无工具记录，但主张了完成或成功 |
| self-report | Agent 自报 | 仅为描述性自述，未主张完成 |

## 判定规则（单遍、首中即止）

1. 该主张对应的验证记录中存在明确失败 → failed。
2. 存在明确通过且无失败的验证记录 → external-verification。
3. 无验证记录但有工具调用记录 → tool-evidence（页面同时注「未复验」）。
4. 无验证无工具但主张了完成或成功 → unverified。
5. 仅为描述性自述 → self-report。

「明确通过 / 明确失败」只认检查记录状态字段的原文，受控词表如下：

- 通过：pass、passed、ok、okay、success、succeeded、green、通过、成功、成功通过。
- 失败：fail、failed、failure、error、errored、red、失败、错误、未通过。

词表外的状态值不计入通过或失败，按降档处理并产出 EVIDENCE_STATUS_UNKNOWN 警告，
不猜测语义。混有通过与失败时按失败优先（规则 1 先中）。

## 验证记录的归属

检查记录归属到与之最近的主张（按事件流距离，并列时取更早的主张）。
该规则是确定性的：同一输入的归属结果永远相同且可逐条枚举。
工具调用事件同样按最近主张归属，计入规则 3 的工具记录判定——因此
「仅工具动作、未复验」的主张可判为 tool-evidence；工具调用本身不构成
验证记录，不会触发规则 1 / 规则 2。

## Automation / Schedule 特例

kind 为 automation 或 schedule 的记录，标签固定为「已投递」，证据等级封顶
tool-evidence，永不显示「已执行 / 已完成 / 已验证」。即使别处存在执行与验收
记录，也属于其他主张，不回写投递记录；页面使用独立的「已投递」徽标。

## 脚本化边界裁决（QA 复核点）

- 确定性：给定相同输入，等级判定结果永远相同且可逐条枚举。
- 无语义理解：验证记录匹配只按受控词表与事件距离进行，不做意图推断。
- 失败可预测：唯一失败模式是「状态词表外的值」，处理为归入低档并出警告。
